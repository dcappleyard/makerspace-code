# wled_lighting_tools — Lighted Sculpture show runner

Python service on a Raspberry Pi that streams animations to a QuinLED Dig-Uno running **stock WLED** over DDP, on a sunset-based schedule, plus a simulator for developing shows without the hardware.

**[PROJECT.md](PROJECT.md) is the authoritative spec** — hardware, architecture, DDP details, open items, questions, and milestones. Read it before making changes and keep it current when decisions are made.

Key facts (details in PROJECT.md):
- 4 × 50 px 12V WS2811 strings in use = **200 px**. Output 1 (GPIO16): px 0–99; output 2 (GPIO3): px 100–199. A 5th string is a spare, not installed.
- Location is **Madison, WI** (~43.07 N, -89.40 W), America/Chicago.
- WLED firmware is never modified; control is DDP (UDP 4048) + JSON API only. Controller host comes from config, never hardcoded.
- Sculpture: double helix of 10 base pairs, each two "lollipops" (stem + flat ring) on a central rod. `pixels.csv` is generated by `pixel_map.py` (stdlib only) — edit its constants and rerun, don't hand-edit the CSV. Which strand is on output 1 is unknown: `OUTPUT1_STRAND` / `--swap-strands`.
- Show interface: `render(t, xyz, meta) -> np.ndarray[N,3] uint8`; `meta` = per-pixel labels (strand, base_pair, part, slot).

Files so far: `wled/ddp.py` (DDPSender + Streamer thread), `wled/api.py` (JSON API, stdlib), `testpattern.py` (bench CLI; procedure in README.md), `pixel_map.py`. Runtime host goes in git-ignored `config.yaml` (from `config.example.yaml`).

Conventions: follow `../CLAUDE.md` — unpinned `requirements.txt`, no test suite or heavier tooling unless asked.
